## 分析上游仓库 ShiJiang-hub/2025-E- 的视觉代码

- 来源：https://github.com/ShiJiang-hub/2025-E- （2025 电赛 E 题，国一）。直连 git clone 被代理拦截（502），改用 GitHub API（api.github.com）+ WebFetch 逐文件取 base64 再解码成功。
- 视觉代码位置：`软件设计/树莓派程序/`，共 3 文件：
  - `c1.py`：主程序，类 `A4RectangleDetector`，OpenCV 几何法。
  - `jiaozheng.py`：`CameraCalibration` 鱼眼去畸变（cv2.fisheye）。
  - `calibration_result.yaml`：内参 K(fx468.1,fy467.8,cx336.1,cy228.2)、D 四系数、DIM 640x480。
- 技术栈：Python3 + OpenCV + NumPy + pyserial + PyYAML；树莓派 B3 + USB 免驱相机（MJPEG 60fps）；串口 115200，协议 `@[靶心x,y];[激光x,y]%`。
- 识别逻辑：翻转→鱼眼去畸变→灰度+双边滤波→Canny(50,150)→findContours(RETR_TREE)→四边形筛选（面积 2000~80000、四角≥70°、长宽比 A4 1.52±0.4）→取最小面积内框→透视变换成 171x260 正视图→正视图中心逆映射回原图=靶心。
- 关键点：靶心用「透视变换+中心反投影」而非质心；「激光中心」非识别，而是用面积二次拟合 `-1.928e-9*a²+4.398e-4*a+318.7`，y 恒 251，用于补偿相机/激光视差。
- STM32H750 侧：entry.c 状态机收包→FreeRTOS 队列→dataRec.c `Position_DataRead`(仅整数解析)→control.c `yunTaiVelocityControl` 速度环 PD(Kp.532,Kd1.49,Ki0)+IMU 反自旋(w[2]*2.4)+行进前馈(SpeedInverse*95.7)；`detectionAiming` 误差≤3px 触发打点。
- 效果（README）：静止 2s 内 ≤1.5cm；随机朝向 4s 内 ≤1.8cm；行驶中 2 圈 ≤8cm。
- 隐患：直角阈值 70° 偏宽、长宽比容差 ±0.4 过宽易误检；激光中心拟合泛化差；无跟踪外推；串口无校验；大量硬编码。

## 第八轮（r6）：真机"锁定效果不佳 + 远距离完全锁不住"

### 用户给的证据
MaixVision 截图：近处 `valid=True 候选=paper px/cm 10.37~16.07`（抖）、
远处 `valid=False 候选=-` + 每帧 `[diag] 诊断输出失败: must be real number, not NoneType`。

### 五个根因（全部经 PC 复现 + 修复验证）
1. **`MIN_AREA_RATIO = 0.02` 锁死距离（最致命）**：1280x720 的 2% = 18432px，
   A4 长宽比 1.414 → 要求靶纸宽 ≥114px；165cm 处才 141px（6.7px/cm）
   ⇒ **超过约 2.0m，任何阈值都产生不出候选轮廓**（日志里连候选都没有，不是分数低）。
   → 改 `0.002`；四边形面积下限拆成独立的 `MIN_QUAD_AREA_RATIO = 0.0006`。
2. **`MASK_FG_MIN/MAX = 0.002/0.93` 同样按"靶纸占满画面"定的**：远距离环只占 0.06~0.15%
   （低于下限）、暗背景前景占比冲到 0.996（高于上限）→ 每个阈值都被"前景占比越界"跳过。
   → 改 `0.0003/0.999`（防误检交给 `SCORE_*`）。
3. **形态学核把细环腐蚀掉**：远距离胶带在缩小图上只有 1~2px，`MORPH_OPEN_K=3` 直接抹掉；
   环一没，纸面就不再是"内孔"，两族候选同时失效。
   → 把形态学也当成搜索维度：`MORPH_SEARCH/MORPH_OPEN_K_FINE=1/MORPH_CLOSE_K_FINE=3`，
   先常规核扫全部阈值、都不行再换精细核扫一遍，命中连形态档一起锁。
4. **失败时锁定阈值，把兜底路径一起锁死**：`_detect_on` 全扫失败后原写
   `_th_lock = cfg.BLACK_THRESH`，于是"缩小图没找到"的错误结论被固定，紧接着的
   "全分辨率升级那一遍"只试这一个阈值 → 继续失败（日志每帧只有一条 th=95 行）。
   → 失败时**保持解锁**，只用 `_next_sweep` 限流；升级那一遍 `force_sweep=True` 强制全扫。
5. **极值法在小目标上取错角（会给错误中心，比漏检更糟）**：靶纸接近轴对齐且只有 40~60px 时，
   "y 最小"是整条上边，argmin 可能取到边的中段；得到的 4 点互异、排出来还凸、
   面积/长宽比全正常，中心却偏 **14~20px**。
   → 两条处置：`geometry.opp_side_convergence()`（对边夹角必须与"对边长度差"自洽，
   合法姿态余量 ≤10.3° vs 假四边形 30.4°，取 `OPP_ANGLE_SLACK=18`）+
   `geometry.quad_fit_error()`（轮廓点到四边形边界的平均距离，真假差 0.5px vs 14px），
   让"极值法"和"多方向极值法"两套候选用贴合误差竞争。

### 顺带修掉
- `main.diag_line` 崩溃：某条诊断记录少填字段 → `"%.2f" % None` 抛 TypeError → **整行信息全丢**。
  → 新增 `detector._dbg_rec()` 统一构造（字段齐全）+ 打印处 `_n(rec,k)` 兜底。
- `mask.png` 之外新增落盘 `mask_morph.png`（过完形态学的二值图），一眼看出"环是阈值没切出来
  还是被形态学吃掉了"。
- `geometry.quad_area()` 的鞋带公式下标写错，返回真实面积的 **2 倍**（下游只用比值/比较所以没暴露，
  但 `is_valid_quad` 的面积下限是按它写的）→ 已修正。
- `ASPECT_MAX` 从 1.6 放宽到 2.10（原先比结构分里的 `SCORE_ASPECT_HI=2.45` 还严，
  会把强透视的合法靶纸在最后一道几何校验拦掉）。

### 实测（全部 PC 门禁通过）
- 硬场景 **18/18 检出**（0.03~0.72px；旧策略 10/18 失败），负样本 **5/5 拒检**。
- 远距 3.4m / 极远 5.2m 各 40 帧（每帧新建探测器+加噪+失焦）：检出 40/40，

## 性能优化：0.1fps -> 可用（DeepSeek 轨 / 第 4 轮）

**触发**：用户反馈"能准确识别矩形框中点，但帧率只剩 0.1fps"。

**定位方法（关键）**：先用 `tools/profile_hotspots.py` 量到"算法本身在 PC 上端到端 3.4ms
（≈298fps）"—— 证明**不是算法复杂度问题，而是某些输入下复杂度爆炸 + 单帧无上界**。
随后用 `git show HEAD:vision/detector.py` 把优化前的实现另存成一个临时包，
**在同一进程里交错测量做严格 A/B**（机器负载波动会让跨进程对比完全不可信，
这一点本次踩到了：同一个 `cv2.morphologyEx` 两次测出来差 7 倍）。

**三个真凶（都有实测数字）**
1. `findContours` 在噪声/纹理掩膜上要创建 2 万条轮廓对象（精细形态档 lvl=1 **不做开运算**，
   噪点原样保留，是最容易爆的一档，而 `MORPH_SEARCH=True` 让它每轮扫描都会跑到）。
   单张掩膜最慢 **293ms**（PC/x86）。旧实现还在其上逐条做 `minAreaRect`（内部算凸包）。
2. **"缩小图没锁住 → 全分辨率升级"那一趟 `force_sweep=True` 会无视已有锁定，
   把 12 阈值 × 2 形态档 = 24 个掩膜在整幅全分辨率上重扫。** 远距离时胶带在 0.5 倍图上
   只有 1px、粗定位很容易失败 → **每一帧**都掉进这条路。
   实测复现：**28 个掩膜/帧、506ms/帧**（PC）—— 板上乘以十几倍正好就是 0.1fps。
3. `debug_dump` 每次失败往 flash 写 3 张全分辨率 PNG（板上秒级），
   却和"打印诊断"共用 2 秒节流。

**处置（全部"只加天花板、不减能力"）**
- `boundary_estimate()`：隔点采样统计 0/255 跳变数（0.3ms），与 `findContours` 耗时**严格单调**
  相关（est 20~600→1~3ms；9k→17ms；72k→190ms）。超过 `FRAG_BOUNDARY_EST=13000`
  才转走连通域预筛 `_survivor_contours`（只对幸存块描边）+ `_top_contours` 按点数截断。
  → 单张最慢 **293ms → 82ms**；**干净掩膜完全不走这条路，行为与优化前逐位一致**。
- `_mask_specs` 把"上一帧锁定值"排到扫描表**最前面** → 全分辨率上第 1 个掩膜就命中。
- `_masks` 改**生成器**（旧实现一次性把所有掩膜算完再返回，`break` 只省了描边、
  省不掉阈值化+形态学）+ 每帧预算 `MAX_MASKS_FULL=8` + 轮转游标。
- 新增**帧间 ROI 跟踪** `_try_track`（默认开）：用上一帧框扩 25% 只解一小块，
  带**跳变门限**与裁剪检测，跟丢自动回落全局搜索 → 稳态再省约 36%。
- `debug_dump` 独立节流（20s）+ 限量（3 次）+ 可降采样 + PNG 压缩级别 1。
- `[fps]` 行新增 `算法=xx.xms 掩膜=N [各趟耗时]` —— **`掩膜=N` 是帧率的头号指标**。

**效果**：远距离小靶场景 **28 掩膜/506ms → 12 掩膜/85ms（6x）**；找到目标时只需 2 个掩膜。

**踩过的坑（重要）**
- **连通域统计（CC）无条件预筛是错的**：它给每张掩膜固定加 17~20ms，
  干净场景反而劣化十几倍。必须是"按需触发"，且触发阈值要用**实测交叉点**
  （曾取 8000，实测在 est≈9000 处反而劣化 2 倍；13000 才对）。
- 坑的根源：`(bw>0).mean()` 会先分配整幅 bool 数组 → 换成 `cv2.countNonZero`。

## 抗抖动：车一晃锁框中心就偏（DeepSeek 轨 / 第 5 轮）

**触发**：用户反馈"抖动时锁框中心偏移，小车移动造成较大抖动，要求用滤波算法保证稳定锁定"。
板端日志（帧率已正常 11~16fps、`掩膜=1`）显示中心在几十~上百像素间跳、`px/cm` 在
22↔12.5 之间跳、候选族 ring/paper 来回切。

**定位方法（关键，结论与直觉相反）**：先写 `tools/test_jitter.py`（合成靶纸 + 模拟车身晃动
+ 定向运动模糊，真值已知）**复现**，再量化：

| | 抖动下中心误差 均值/最大 |
|---|---|
| 原始解算（完全不滤波） | **0.10 / 0.39 px** |
| One Euro(static)（= 现状） | **8.06 / 27.26 px** |

→ **偏移不是检测算错了，是滤波器跟不动**。抖动让靶心的像以 1.7~5Hz 晃几十像素，
这是**必须跟踪的真实运动**（云台靠它瞄准），当噪声滤掉 = 照着几帧前的位置打。

**先验证再改**：分别关掉 `REFINE_CORNERS` / 形态学 / ROI 跟踪 / 换阈值策略，
误差都不变 → 排除了检测侧原因，确认问题只在滤波器。这一步省了大量试错。

**处置**：新增 `vision/tracker.py`（常数速度卡尔曼 + 自适应过程噪声 + 新息门限），
把"跟运动"与"防误锁"解耦。`FILTER_MODE/FILTER_PARAMS` 保留（One Euro 现在只用于尺度通道）。

**实测（`tools/test_jitter.py`）**
| 场景 | 原始测量 | 新跟踪器 | One Euro(旧) |
|---|---|---|---|
| 纯抖动 误差均值/最大 | 0.09/0.28 | **0.14/0.41** | 8.06/27.26 |
| 静止 帧间跳变均值 | 0.0168 | **0.0034** | — |
| 单元：平常（跟手） | 0.62 | **0.62**（=原始，零滞后） | 25.99 |
| 单元：离群帧误差 | 113.90 | **11.44** | 45.72 |

**踩过的坑（都是"看起来对、实测错"）**
1. **机动判据必须扣掉测量噪声**：直接拿"新息²"当机动强度 → 静止靶纸的新息就是噪声本身
   → q 被噪声抬起 → 滤波器转去追噪声 → 抑噪能力归零（实测只降 1%，与噪声大小无关）。
   正解：`机动倍率 = max(0, 新息²/meas_var − 1)`。
2. **映射必须按对数**：q 跨 4 个数量级，线性映射下倍率只要有一点余量（噪声波动带来的 0.04）
   就一步跳到 1.6e6，"静止重平滑"同样失效。
3. **滑动的单帧截顶必须有正的绝对下限**：只用"当前值×N"做上限时，估计一旦到 0
   （excess 可以正好为 0）就**永久锁死**，跟手能力整段消失。
4. **门限必须能自我放开**：真运动与误锁在"单帧跳变"上不可区分；门限不放开会形成
   "预测停在旧位置 → 后续测量显得更离谱 → 继续拒信"的**级联锁死**（实测连续保持十几帧、
   误差漂到 200px）。放开的自由度只给中心，**形状门限永不放开**。
5. **离群点绝不能喂养"机动尺度"**：即使做了 9 倍截顶，beta≈0.09 下单帧仍让它涨 72%，
   十几次离群就把门限自己撑松 → 后面全部放行。
6. **一个坏测量会污染速度**：高过程噪声下卡尔曼速度增益 K1≈30，一个 84px 离群点能把速度
   一次改掉 1800px/s、下一帧预测飞出去 208px。→ 加"单帧速度修正量上限"。
7. **统计门限（新息几个 sigma）不能当抗误锁主力**：q 自适应到上限后过程噪声把新息协方差
   抬得很大，84px 的离群点只算 3.65σ → 直接放行。必须有一条"物理量纲"的硬门限。
8. 门限尺度**不能用"相对目标尺寸"**：大目标上的一次误锁可能只偏自身尺寸 10%，拦不住。
   正解：`max(绝对下限, K × 近期新息尺度)`。
