**源码级结论（MaixCDK，已抓源核对）**：

### 补证（抓源复核，确认修复边界）
- `img_trans` 是 **`static ImageTrans*`（maix_display.cpp L30）**，懒创建：首次 `show()` 时
  `if(!img_trans && maixvision_mode()) img_trans = new ImageTrans(...)`（L131-133），
  `send_to_maixvision()` 同样会 `else if(maixvision_mode()){ 建; send }`（L381-386）——
  ⇒ 两处都以 `maixvision_mode()`（即 `getenv("MAIXVISION")=="1"`）为唯一开关，**设 0 后两者都跳过**。
- **全仓只 display 模块读 `MAIXVISION`**：抽查 `maix_app.cpp`/`maix_sys.cpp`/`maix_vision.cpp`/
  `maix_camera_maixcam2.cpp`/`maix_comm_base.cpp` **均无**该符号 ⇒ 改环境变量不影响相机/系统/通信，
  副作用面仅限「MaixVision 画面预览」。修复范围确认为最小闭包。

### 「之前不卡，现在卡」的真相（官方文档核对）
- **图传与本地屏同源**：官方 MaixVision 文档明确 `disp.show(img)` = 同时上屏 + 发送到 MaixVision；
  `MAIXVISION=1` 由 **MaixVision IDE「在线运行」时注入**（设备本地启动 / 装成 app 从桌面跑 = 无该变量 = 无图传）。
- **官方文档原文：点击 MaixVision 右上角「暂停」按钮 = 停止发送图像到 MaixVision。**
  ⇒ 预览不处于收图状态时图传握手不完成 → `img_trans` 内部 `init` 恒 false → 每次 `show()` 忙等 500ms。
  这就是「预览一暂停/未开，帧率就掉到 ~2fps」的直接机理。
- **判据**：v0.4.4 探针实测 505ms，**本身即证明**当时是「从 IDE 远程运行 + 预览未在收图」；
  设备本地启动只会 1~5ms。⇒ **卡不卡取决于「启动方式 + 预览是否在收图」，与改动多少无关。**
- 最简方案（零代码）：① 从设备本地启动应用 → 只上屏、无图传、全帧；
  ② 从 IDE 跑但保持预览面板连接（别停在暂停态）→ 原生图传正常，也不忙等。
  我们的 `DISABLE_MAIXVISION_STREAM` 只是把默认锁到 ①；要回 ② 改一行 `False`。
