# 25E 靶心识别 · MaixCAM / MaixCAM2

2025 全国大学生电子设计竞赛本科组 **E 题《简易自行瞄准装置》** 的视觉模块：
由 **A4 靶纸四周 1.8cm 黑胶带勾出的矩形框**，反算 **靶心像素坐标 (u, v)** 与 **局部尺度 px_per_cm**，
通过串口交给云台主控解算激光指向。

> 靶心是红色记号笔点的点（≤0.1cm），在 165cm 处只有约 **0.67px**，物理上不可见。
> 所以靶心 **只能由黑框矩形几何反算**，不能靠找红点。

## 三、关于「帧缓冲内存不足」报错

报错提到"当前分辨率/格式下算法需要的帧缓冲内存超过可用内存"——它指的是图像模块的
**帧缓冲内存池**（早期 image 模块把图像放在固定池里；MaixPy v4 在 Linux 上对应
相机/显示/图像共用的**快速连续内存 CMM/ION**）。官方文档也明确提示：
**高分辨率 + MaixVision 图像预览会因内存不足导致代码运行异常**。

本工程把这条链路上的内存占用逐项压掉了：

| 项 | 旧写法 | 现写法 | 效果 |
|---|---|---|---|
| 相机格式 | `FMT_RGB888`（3 B/px） | `FMT_GRAYSCALE`（1 B/px）直出 | **省 3×** |
| 相机缓冲 | `buff_num=3` | `buff_num=2` | 再省 1/3 |
| 1280x720 摄像头缓冲 | 约 **8.3 MB** | 约 **1.8 MB** | **约 4.6×** |
| 处理分辨率 | 整幅全分辨率 | 缩小图(1/4 像素)粗定位 + 靶纸外接框内全分辨率精算 | 中间缓冲只与"目标大小"相关 |
| 全分辨率兜底 | `find_rects`（要生成梯度浮点图） | 已移除 | 去掉一个大内存项 |
| 显示画布 | 每帧新建 | 启动时分配一次并复用 | 零逐帧分配 |

相机打开失败会自动按「更省内存档位」降级重试，并把 `sys.memory_info()` 打印出来。

若仍然内存不足，按顺序再做：
1. 跑高分辨率时**关掉 MaixVision 的图像预览**；
2. `config.py` 把 `PROFILE` 改成 `"lowmem"`（640x480）或 `"lowmem32"`（单缓冲）；
3. MaixCAM2 可改 `/boot/configs` 的 `maix_memory_cmm`（单位 MiB，默认 `-1`）加大快速内存；
4. `SHOW = False` 关掉显示，纯串口模块模式（最省）。

## 四、算法流程

```
灰度(相机直出) → ① 黑阈值二值化 + 形态学开/闭净化        → 锁定黑胶带
              → ② 候选轮廓结构打分，挑出"靶纸框"（见 4.1）
              → ③ 轮廓上 x最小/x最大/y最小/y最大 四个极值顶点
              → ④ 排成 [左上 右上 右下 左下]
              → ⑤ 两条对角线 (TL-BR) ∩ (TR-BL) 的交点 = 靶心
              → ⑥ 反算 px_per_cm（环族按 A4 外沿 21.0×29.7；亮面族按内沿 17.4×26.1）
              → ⑦ One Euro 滤波抑制抖动
              → ⑧ 屏幕绘制 + 可选串口输出
```

**为什么"对角线交点"就是靶心（关键结论）**：靶纸黑框是矩形，透视成像是单应变换 H，
它把"直线映射为直线、交点映射为交点"，所以矩形对角线在图像中的交点，恰好是矩形中心
（=靶心）的投影。**只要四角点准，靶心就是精确解，不需要再求解 H**。
（这也是"取外框外沿还是内沿"不影响中心、只影响尺度的原因：两者同心。）

**两级解算**：先在缩小图（`WORK_SCALE`，默认 0.5，1/4 像素量）上粗定位板框，
再在粗定位外接框（靶纸 + 8% 余量）内用**全分辨率**重解一遍。缩小图会把边缘量化到小的
像素栅格上（约 ±1 个原始像素的偏置），这一遍把它消掉，精度回到全分辨率水平，
而中间缓冲的内存只与目标在画面中的大小相关。外接框贴边（可能被裁断）时自动弃用该结果。

### 4.1 ② 描边：为什么不能"取面积最大的黑轮廓"

合成图上"取最大黑轮廓"够用，**真机上极易锁错**，只要出现下面任一情况，最大轮廓就不是黑胶带框：

- **深色背景 / 桌面 / 机箱** —— 面积比胶带框更大，甚至与框连成一片；
- 画面里有比靶纸**更大的深色干扰物**（显示器、垫子、投影阴影）；
- 黑框**贴到画面边缘** —— 轮廓被画面边界切断，"四角"变成画面角；
- **曝光没标定好** —— 固定阈值下胶带进不了二值图（或整幅全黑）。

所以改成**按结构打分**（`SELECT_MODE="score"`，默认；`="largest"` 是旧行为，仅供对照）。
判据是**与光照无关**的：外沿接近矩形、内孔占比像"1.8cm 胶带围出 21×29.7"、长宽比像 A4、
以及"深色带"与"亮面"的实际灰度对比度。

### 4.2 两族互补候选（这是解决"锁不住框"的核心）

胶带环有一个致命弱点：**一旦胶带与任何深色区域相邻（暗背景、桌面、干扰物），
两者在二值图里会连成一片，胶带的外沿就不再是一条闭合轮廓** —— 此时无论怎么调阈值都取不到。
但这时**纸面（= 胶带内沿围出的区域）的轮廓始终完好**。所以同时找两个互补结构：

| 族 | 是什么 | 优点 | 缺点 |
|---|---|---|---|
| `ring`（深色环） | 黑胶带**外沿**（≈纸边） | 中心最准（外沿贴着纸边，胶带贴得不均匀也不影响） | 与深色背景/干扰相邻时轮廓被吃掉 |
| `paper`（亮面矩形） | 纸面 = 胶带**内沿** | 只要"纸面亮、周围深"就成立，抗上述所有破坏 | 胶带贴得**不均匀**时，内沿中心会相对纸边中心偏一点 |

两者同心（内沿 = 外沿向内收 1.8cm），所以中心都能用。策略是**优先环**（`RING_BONUS`
让分数接近时选外沿），环拿不到才用亮面。运行时 `[fps]` 那行会打印用的是哪一族
（`候选=ring` / `候选=paper`），一眼可辨。

### 4.3 ③″ 阈值自动标定（曝光没标定好时的救命机制）

固定阈值稳定的大前提是"曝光锁定且标定过"。为防现场没标定好，做了两级机制：

- **候选阈值**：`fixed` / `otsu` 都试，用同一套结构分择优；
- **锁定 + 重标定**：一旦选中某个阈值就锁住，后续帧只算这一个（**稳态零额外开销**）；
  连续 `THRESH_RELOCK_MISS` 帧失败才解锁，用 `THRESH_SWEEP`（30…205 共 10 档）重扫一遍。

另外两个"阈值合理性"硬约束（不满足直接跳过该阈值）：掩膜前景占比必须在
`[MASK_FG_MIN, MASK_FG_MAX]`（太低=什么都切不出，太高=把背景都当深色）。
**这两个值必须按"靶纸可能很小"来定**：远距离时胶带环只占画面 0.06~0.15%，
暗背景时"背景+胶带连成一片"会让前景占比冲到 0.996 —— 按 0.002/0.93 写会把这两类
全部越界拦掉。现在是 `0.0003 / 0.999`，防误检交给 `SCORE_*` 结构分（见 4.5）。

> **实测效果**（`tools/test_hardscene.py --ab`，18 个真机级场景：恶劣光照 + 远距离）：
> 旧策略（取最大轮廓）**10/18 失败**；新策略 **18/18 全部检出**，误差 0.03~0.72px。
> 反向验证（5 个"画面里根本没有靶纸"的场景）：旧策略误锁 2 个，新策略 **5/5 正确拒检**。

### 4.4 锁不住框 / 锁错了怎么办（真机排查流程）

**板子上：失败会自动打印诊断，并把原始帧落盘。** 日志长这样：

```
[diag] 灰度 p1/p5/p50/p95/p99=17/26/71/252/254  锁定阈值=95(形态档0)  黑占比=0.637  本帧来自=full
[diag]   阈值95    形态0  候选0    最优[- 分=0.00 fill=0.00 rim=0.00 ring=0.00 长宽比=0.00 对比=0 几何合法=False]
[diag]   阈值150   形态1  候选2    最优[ring 分=1.08 fill=0.96 rim=0.67 ring=0.09 长宽比=1.32 对比=183 几何合法=True]
[dump] 已保存 /root/target_dbg/{frame_gray,mask,mask_morph}.png（阈值=95 形态档=0）
```

> 诊断行以前会抛 `must be real number, not NoneType` 然后**整行丢失**（有的分支少填了字段，
> `"%.2f" % None` 就崩）。现在记录统一由 `detector._dbg_rec()` 构造（字段齐全），
> 打印处再加一层兜底 —— 不会再出现"只有报错、没有信息"的情况。
> 每行末尾的 `形态` 是形态学档位（0 常规 / 1 精细），`本帧来自` 是 coarse/full/roi 哪一趟。

看三件事就能定位：

| 现象 | 说明 | 处置 |
|---|---|---|
| `p1` 很高（比如 118） | 连最暗的胶带都这么亮 —— **曝光过高 / 环境光太强** | 压 `EXPOSURE`，或避开强光/反光 |
| `p99` 很低 | 整幅偏暗（欠曝） | 补光，或提高 `GAIN`/`EXPOSURE` |
| `黑占比=0.000` | 这个阈值下什么都没切出来 | 下次重标定会自动换阈值；也把 `THRESH_CANDIDATES` 保持 `"auto"` |
| 有候选但分数很低 | 形状不符 | 看是哪一项不达标（`fill/rim/ring/长宽比/对比`），再决定调哪个 `SCORE_*` |
| 一个候选都没有 | 轮廓都不成形 | 多是**胶带反光/断裂**，见下 |

**在电脑上：拿一张真机照片离线调**（最快的一条路）：

```bash
python tools/tune_real.py 照片.jpg          # 输出阈值扫描表 + 叠加图 tune_overlay.jpg
python tools/tune_real.py 照片.jpg --tape 2.0   # 胶带实际不是 1.8cm 时改这里
```

它会打印灰度分布、每个阈值下的候选结构、最终用了哪个阈值、锁到的是环还是亮面，
并给出`建议把 Config.BLACK_THRESH 改成 N`。**真机锁不住时，把这张照片和这张扫描表发我，
按它精确调 `SCORE_*` 参数即可，不用再靠猜。**

照片可以用板子上的 `/root/target_dbg/frame_gray.png`（失败时自动落盘），
或直接手机拍一张同角度的照片。

**落盘文件多了** `mask_morph.png`（过完形态学之后的二值图 —— 描边实际看到的就是它）：

| 对比 | 说明 |
|---|---|
| `mask.png` 里环完整、`mask_morph.png` 里环断了/没了 | **形态学核太大，把细胶带环腐蚀掉了**（远距离典型症状）→ 调 `MORPH_OPEN_K` / `MORPH_CLOSE_K`，别调阈值 |
| `mask.png` 里就没有环 | 阈值问题（曝光/反射），走 `tune_real.py` |

### 4.5 远距离锁不住（这一节解释"近了能锁、远了完全锁不住"）

真机实测症状：**1.5m 能锁，2.5m 开始偶尔丢，3m 以外任何阈值都一个框都锁不到** ——
近处完全正常，所以第一反应总以为是阈值/曝光问题，其实不是。三个原因，全在"面积与尺度"上：

**原因① 候选轮廓的面积门按"靶纸占满画面"定的（最致命）**

`MIN_AREA_RATIO = 0.02` 表示"候选轮廓面积 ≥ 画面的 2%"。算一下就知道它锁死了距离：

```
1280x720 的 2% = 18432 px；A4 长宽比 1.414 -> 要求靶纸宽 >= 114 px
165cm 处靶纸才 141px 宽（约 6.7 px/cm）
=> 距离超过约 2.0m，靶纸面积掉到 2% 以下，**任何阈值都产生不出候选轮廓**
```

于是真机日志里连一条候选都没有 —— 不是"分数低"，是**候选根本没生成**。
改成 `MIN_AREA_RATIO = 0.002`（约 5.6m 仍可检出），并把"四边形面积下限"拆成
单独的 `MIN_QUAD_AREA_RATIO`（更小）。真正的噪声/误检靠 `SCORE_*` 结构打分挡，
不该靠"面积要够大"挡。

**原因② 形态学核太大，把细胶带环直接抹掉**

远距离时胶带在缩小图（`WORK_SCALE=0.5`）上只有 1~2px 宽，`MORPH_OPEN_K=3` 的开运算
会把它**整个腐蚀掉**。环一没，纸面就不再是"内孔"，**两族候选同时失效**。
处置：把形态学也当成一个**搜索维度**（和阈值一样）——
`MORPH_SEARCH=True`、`MORPH_OPEN_K_FINE=1`、`MORPH_CLOSE_K_FINE=3`。
先按常规核扫一遍全部阈值，都不行再整体换成精细核扫一遍；命中后连形态档一起锁住，
所以近处（常规够用）不会为远距离付额外代价。

**原因③ 灰度探针的步长写死了**

判"纸面外面是不是真的深色胶带"要沿法线方向移几个像素去采样。原来步长是
`min(8, max(2, ...))` —— **下限恒为 2px**。远距离胶带只有 1~2px 宽时，移 2px 直接跨到
背景上，测出来的"对比度"是背景的对比度，于是"亮面族"的硬门槛（`PAPER_MIN_CONTRAST`）
误判。改成**按候选自身的胶带宽度自适应**（由"外轮廓面积 vs 内孔面积"估出
`(√A外 − √A内)/2`，见 `detector.ring_thickness_px`），移一个"半胶带宽"。

**另外还有一条坑：失败时把阈值"锁定"成配置值，会把兜底路径一起锁死**

`_detect_on` 全扫失败后，原实现写 `_th_lock = cfg.BLACK_THRESH`。
于是"缩小图这一遍没找到"这个**错误结论被固定下来**，紧接着的"全分辨率升级那一遍"
就只试这一个阈值 —— 继续失败。真机表现：远距离怎么都锁不住，而且日志里每帧只有
一条 `阈值=95` 的诊断行。正确做法是**失败时保持解锁**，只用 `_next_sweep` 限流；
升级那一遍用 `force_sweep=True` 强制全扫。

**还有一个"错得更隐蔽"的：极值法在小目标上取错角（会给出错误中心，比漏检更糟）**

靶纸接近轴对齐且只有 40~60px 时，矩形的**上边整条都是"y 最小"**，
`argmin` 可能取到边的**中段**而不是右上角（x 最大同理）。这样得到的 4 个点
互异、排出来还是**凸的**、面积/长宽比全正常 —— 骗过了所有几何校验，中心却偏 14~20px。

两个处置：

1. `geometry.opp_side_convergence()`：投影矩形的对边夹角必须与"对边长度差"自洽
   （有透视收敛就必然有长度差）。实测合法姿态（含 θ=70° 强透视）富余量 ≤10.3°，
   而这种假四边形是 30.4° —— 取 `OPP_ANGLE_SLACK = 18` 正好分开。
2. `geometry.quad_fit_error()`：轮廓点（等距 64 点）到四边形边界的**平均距离**。
   真框 ~0.5px；假四边形会有一条边从轮廓中间横切过去，均值上到几像素。
   现在 `extract_ordered_corners` 同时算出"极值法"和"多方向极值法"两套候选，
   **用贴合误差当裁判取更贴合的那个** —— 极值法失手时自动让位。

> 顺带修掉一个潜伏的 2 倍 bug：`quad_area()` 用的恒等式写错了一个下标，
> 返回的是真实面积的 **2 倍**。下游几乎只用它做比值/比较所以一直没暴露，
> 但 `is_valid_quad` 的"面积下限"是按它写的（门槛实际只有标称的一半）。已修正。

**实测（`tools/test_hardscene.py`，新增 6 个远距离场景）**

| 场景 | 靶纸占画面 | 旧策略 | 新策略 |
|---|---|---|---|
| 远距 3.4m（62x83px） | 0.56% | 未检出 | **0.46px** |
| 远距 + 亮墙 / 暗背景 / 环境光 | 0.56% | 未检出 | **0.47 / 0.03 / 0.47px** |
| 极远 5.2m（40x56px） | 0.24% | 未检出 | **0.48px** |
| 远距 40 帧连续（每帧新建探测器，加噪+失焦） | — | — | 检出 **40/40**，误差均值 0.46~0.48px、最大 0.70px、帧间跳变 ≤0.41px |

## 五、现场标定清单（`config.py`）

1. `EXPOSURE` / `GAIN` / `WB_GAIN` —— 锁定曝光与白平衡是固定阈值稳定的前提。
   白平衡初值 MaixCAM2 用 `[0.0682, 0, 0, 0.04897]`，MaixCAM 用 `[0.134, 0.0625, 0.0625, 0.1239]`。
2. `TAPE_W_CM = 1.8` —— 胶带实际宽度。用"亮面族"时按它换算 px_per_cm，贴的不是 1.8cm 就改。
3. `BLACK_THRESH = 95` —— 按实际黑白灰度分布微调；不确定就**保持 `THRESH_CANDIDATES="auto"`**，
   它会在 fixed/otsu/扫描表里按结构分自动择优并锁定。
4. `SELECT_MODE = "score"` —— **务必保持 score**（`"largest"` 是旧的"取最大轮廓"，真机极不稳）。
5. `DEBUG_DUMP = True` / `DEBUG_DIR` —— 锁框失败时把原始帧落盘，是排查的第一手材料。
6. `UART_PORT` / `UART_BAUD` —— 按实际接线改，改完把 `ENABLE_UART = True`。
7. `H_MIRROR` / `V_FLIP` —— 相机装反了改这里。
8. `ROI` —— 若已知靶纸只可能出现在画面某区域，填 `[x, y, w, h]` 可进一步省内存、提速。
9. `DEBUG_SHAPE = True` —— 启动首帧打印一行 `[gray] format=.. shape=.. ndim=..`。
   换板子 / 换固件后看一眼就知道灰度桥接走了哪条分支（`image2cv` 的返回形状各固件不统一）。
10. **`MIN_AREA_RATIO = 0.002`** —— **直接决定"最远能识别多远"**，改大之前先读 4.5。
    它同时是"候选轮廓面积下限"和"四边形面积下限"，写成 0.02 时超过 2.0m 就完全锁不住。
11. `MORPH_SEARCH = True` / `MORPH_OPEN_K_FINE` / `MORPH_CLOSE_K_FINE` —— 远距离细环救回机制，
    见 4.5 原因②。核太大把环腐蚀掉时，`mask_morph.png` 一眼能看出来。
12. `OPP_ANGLE_SLACK = 18.0` —— 对边收敛自洽性容差，挡"极值法取错角"造出来的假四边形（4.5）。
13. `MASK_FG_MIN / MASK_FG_MAX` —— 掩膜前景占比的合理性区间。**也是按"靶纸可能很小"定的**：
    写成 `0.002 / 0.93` 时，远距离（环只占 0.06~0.15%）和暗背景（前景占比冲到 0.996）
    都会被越界拦掉。现在是 `0.0003 / 0.999`。

> 一般**不需要**动 `SCORE_*` 那一组参数。真锁不住时先按 4.4 的流程拿到诊断/照片，
> 再按数据决定改哪个 —— 直接猜着调很容易把"抗误检"调坏。

预检做五件事：**⓪ 源码版本自检**——检查 `main.py` 里灰度形状修复的关键标记是否还在、
两个入口的 `BUILD_ID` 是否一致，专门拦"源码被旧内容覆盖"这类静默回退；
① 主循环整条跑通且**逐帧 valid=True**（检测真的成功，不是"没报错"）；
② 故意插入打不开的档位验证**相机自动降级**；③ 模拟"只下发单个文件"验证会给出**可照做的中文提示**；
④ **`image2cv` 返回形状矩阵**——把 `(H,W)` / `(H,W,1)` / `(1,H,W)` / `(H,1,W)` / `(H,W,3)` / `(H,W,4)` /
`(H,W,2)`（RGB565 打包）逐个喂进去，验证都能转成 `HxW` 单通道，并把桩切成"2 维固件"再整跑一遍主循环。
不必为了一个拼写错误去板子上烧一遍程序。桩模块只验证逻辑跑得通，**不能替代实机联调**。

> **上板前的建议顺序**：`build_single.py --check` → `smoke_main.py` → 再下发到板子。
> 这三步能把"下发了旧文件""单文件版停在旧代码""灰度形状变了"三类事故全部拦在电脑上。

单文件版与模块化版是同一份源码（生成时逐文件指纹校验），实测**逐像素完全一致**：

| 姿态 | 模块化 (u, v) | 单文件 (u, v) | 一致 |
|---|---|---|---|
| 正视 | (639.5000, 364.5000) | (639.5000, 364.5000) | ✅ |
| 旋转 30° | (599.8270, 389.7356) | (599.8270, 389.7356) | ✅ |
| 强透视 | (607.0003, 347.5258) | (607.0003, 347.5258) | ✅ |

用合成透视靶纸图（真值已知）实测（`WORK_SCALE=0.5`，即板端默认档位）：

| 项目 | 结果 |
|---|---|
| 单帧中心误差 | **0.0610 px ≈ 0.0030 cm** |
| 多姿态（旋转 30°/强透视/远近/模糊） | 0.02 ~ 0.53 px（≤0.05 cm） |
| 100 帧加噪+失焦 检出率 | **100%** |
| 重复性 σ | 原始 0.008~0.012 px，滤波后 0.002~0.003 px（目标 <0.5 px）|
| 画面叠加 1.8cm 等效黑色干扰块 | 正确忽略，锁定靶纸外框 |
| **真实光照 + 远距离场景（18 个）** | **18/18 检出**，0.03~0.72 px（旧策略 10/18 失败）|
| **误检场景（5 个，画面无靶纸）** | **5/5 正确拒检**（旧策略误锁 2 个）|
| **远距离（3.4m / 5.2m）40 帧连续** | 检出 **40/40**，误差均值 0.46~0.48 px、最大 0.70 px、帧间跳变 ≤0.41 px |

`WORK_SCALE` 取 1.0 / 0.75 / 0.5 / 0.375 时单帧误差都是 0.0610 px —— 说明两级解算
让"省内存的缩小图粗定位"不再损失精度。

> 说明：靶纸**正视（轴对齐）**时会出现约 0.25~0.53 px 的偏差。这是
> "取 x/y 极值像素"这一方法本身在轴对齐时的半像素栅格约定带来的（旋转/透视姿态下
> 该退化消失），折算约 0.05 cm，远小于 D1 ≤ 2cm 的指标。

## 八、调试小贴士

- 终端每 `PRINT_EVERY` 秒打印一行
  `fps / valid / u / v / px_per_cm / 阈值+形态档 / 候选族 / 解算路径`。
- 解算路径含义：`coarse0.50+roi+extreme` = 缩小图粗定位 + 外接框精算 + **极值顶点法**；
  同一位置出现 `sumdiff` 表示极值点退化（轴对齐）走了 `x+y / x−y` 兜底；
  末尾带 `/paper` 表示用的是**亮面族**（说明深色环被背景吃掉了，详见 4.2）。
- **锁不住框时**先看 `[diag]` 那几行（灰度分布 + 每个阈值的候选结构 + 形态档 + 来自哪一趟），
  再用 `tools/tune_real.py` 拿真机照片离线调 —— 见 4.4；**远距离锁不住直接读 4.5**。
- `tools/debug_overlay.jpg`：绿框=板框、黄点=四顶点、蓝线=两条对角线、红十字=靶心、
  品红叉=合成图真值。
- `tools/hardscene_montage.jpg`：18 个真实光照/远距离场景，绿框=真值、橙框=检出，
  用来肉眼确认"这些恶劣条件都能锁住"。
- 设备上代码实际落在哪：**运行项目** → `/tmp/maixpy_run/`；**安装成应用后** →
  `/root/apps/target_center_25e/`。main.py 会在这两处自动找工程根目录，所以从哪个目录启动都能 import。
- 打包时 `app.yaml` 的 `exclude` 已排除 `tools` / `dist` / `reference` / `maixcam2_rect_center` /
  `.workbuddy`（单文件版**不参与打包**，它只是给「运行当前文件」调试用；装在板上的应用走的是
  模块化源码）。`reference/` 是 upstream 参考资料、`maixcam2_rect_center/` 是**另一个自带 app.yaml
  的独立应用**，都不属于本应用的代码，不进包。
