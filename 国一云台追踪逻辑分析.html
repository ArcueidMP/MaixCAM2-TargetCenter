江南大学 2025 电赛 E 题云台（国一）—— 锁定 / 追踪逻辑分析

分析对象：云台代码.7z → 工程 diansai_yuntai_mc02-yuntai_karman（达妙 MC02 云台板，带卡尔曼滤波版本，作者 ggllxx）
分析结论：该方案“稳定追踪”本质 = IMU 姿态闭环（快内环）× 视觉误差卡尔曼滤波（抗抖）× 增益调度 PID（防超调）× 状态机（防丢帧甩头），四者叠加。

0 · 一句话结论

它不是“视觉直接驱动电机”，而是把**视觉只当作一个缓慢、带噪声的角度误差传感器**：视觉给出的 (Δx, Δy, 距离) 先经过卡尔曼滤波平滑，再经随距离自适应的 PID 转成“目标角度的微调量”，叠加到 IMU 闭环的云台参考角上；云台内环始终由 BMI088 + 四元数 EKF 以 1kHz 做角度/角速度双闭环。视觉慢、内环快，二者解耦——这是它稳的核心。

3 · “锁定”逻辑到底怎么写 —— 状态机驱动

锁定不是单一函数，而是一个按题号 + 板间通信指令推进的有限状态机（enum YunTaiState_e）。核心状态：

状态行为设计意图
WAITING零力抱闸，记录起始 IMU 角、记时、关激光待命，`yawtarget = round(YawTotalAngle/360)*360` 归到最近整圈，避免多圈跳变
TURING以固定步长（0.8°/拍）转向 yawtarget−45°开局先“预瞄”到靶纸一侧，缩短首次搜索时间
TRACKING视觉误差 → 卡尔曼 → PID → 微调云台目标角锁定主状态
SEARCHING在 ±60° 内以 0.2°/拍 往返扫描丢失目标后主动找回，而不是傻等
TRACKING_RUNNING边画圆/边运动边锁定，按圆周进度设动态目标动态题（移动靶/画圆）
防丢帧甩头的关键判据（TRACKING 状态）：
if (Vison_revc_flag && Vison_Frequency >= 20.0f) —— 只有「收到帧 且 帧率 ≥20Hz」才刷新控制；否则降级到 SEARCHING。
这样视觉偶发丢帧时，云台保持上一次目标角（内环继续稳），不会因为一次脏数据乱甩。

锁定核心代码（每拍执行）

// 1) 限幅，防止脏数据/异常值冲击
LIMIT_MIN_MAX(opencv_Vision_data[0], -100.0f, 100.0f);   // Δx
LIMIT_MIN_MAX(opencv_Vision_data[1], -100.0f, 100.0f);   // Δy
LIMIT_MIN_MAX(opencv_Vision_data[2],  500.0f, 1560.0f);  // 距离(用于增益调度)

// 2) 卡尔曼滤波（位置+速度 2 状态）
yaw_error_kf.MeasuredVector[0]  = opencv_Vision_data[0];
filtered_yaw_error   = Kalman_Filter_Update(&yaw_error_kf)[0];
pitch_error_kf.MeasuredVector[0]= opencv_Vision_data[1];
filtered_pitch_error = Kalman_Filter_Update(&pitch_error_kf)[0];

// 3) 追踪 PID（目标 = 0）
yaw_tracking_pid_output   = PIDCalculate(&yaw_tracking_pid,   filtered_yaw_error,   0);
pitch_tracking_pid_output = PIDCalculate(&pitch_tracking_pid, filtered_pitch_error, 0);

// 4) 增量式角度修正 —— 注意是 "目标角 -= 增益 * 输出" ，且增益随距离自适应
gimbal_cmd_send.yaw   -= yaw_tracking_pid_output
                          * mapping(opencv_Vision_data[2], 500.0f, 1560.0f,
                                    yaw_control_kxmax,   // 近：0.001
                                    yaw_control_kxmin);  // 远：0.0005
gimbal_cmd_send.pitch += 0.001f * pitch_tracking_pid_output;

本质：把“图像误差”当作闭环偏差，用 PI(D) 把偏差驱动到 0；误差→0 即“锁定”。云台从不直接信视觉的绝对位置，只信视觉的“还要往哪边挪一点”。

4 · 为什么稳 —— 四个可复用的工程决策

① 卡尔曼滤波：把视觉误差当带速度的状态来估（抗抖/抗丢帧）

模型 
状态 x = [误差, 误差变化率]
F = [1, 0.005]   // dt=5ms(200Hz)
    [0, 1    ]
Q = diag(0.1, 1.0)
R = 1.0
P0 = diag(5, 5)
StateMinVariance = 0.001  // 防过度收敛
UseAutoAdjustment = 1
为什么有效
  • 2 状态常速模型：滤掉图像抖动噪声，又保留运动趋势（不迟钝）。
  • UseAutoAdjustment=1：某一帧 z=0（无效/丢帧）时，滤波器只预测不更新，自动退化——丢帧不跳变。
  • StateMinVariance 防止 P 收敛过小后“迟钝、跟不上缓慢漂移”。

注：dt 取 5ms（对应 200Hz 控制节拍），与 Robot 任务节拍一致；这是“视觉低频、内环高频”解耦的量化体现。

② 增益调度（Gain Scheduling）：远近距离用不同控制力度防超调

参数含义值
yaw_control_kxmax / kxminyaw 误差→目标角 的换算增益（近 / 远）0.0010 / 0.0005
pitch_control_kxmax / kxminpitch 误差→目标角 的换算增益（近 / 远）0.0010 / 0.0004

用 mapping(距离, 500, 1560, kxmax, kxmin) 把“同一像素误差”按距离折算：近距小步、远距更稳，避免远距离时一个像素抖动被放大成大幅摆动。这是它比“固定增益”稳的关键调度之一。

③ 追踪 PID 与“分段/复位”策略

环KpKiKd限幅备注
yaw_tracking_pid1.53.00.07±100 / MaxOut 200用 PID_ChangingIntegrationRate 变积分抗饱和
pitch_tracking_pid1.02.00.05±100 / MaxOut 200同上

动态题里还用了在线改增益的巧招：转向瞬间 Kp=3.0, Ki=0, Iout=0（纯比例快速跟），稳定后切回 Kp=2.0, Ki=4.0（加积分消静差）——相当于“粗调/精调”两套参数自动切换。

④ 内环：IMU 姿态闭环 + 前馈，把“稳”做扎实

gimbal 应用里 yaw/pitch 都不是“位置环”，而是以 IMU 角度为反馈的双闭环，并叠加前馈：

// Yaw = GM6020，反馈来自 IMU（OTHER_FEED）
outer_loop_type = ANGLE_LOOP; close_loop_type = SPEED_LOOP | ANGLE_LOOP;
.other_angle_feedback_ptr = &gimba_IMU_data->YawTotalAngle; // 角度反馈=IMU
.other_speed_feedback_ptr = &gimba_IMU_data->Gyro[2];      // 角速度反馈=陀螺
.feedforward_flag = SPEED_FEEDFORWARD | CURRENT_FEEDFORWARD; // 速度+电流前馈

// 速度前馈：由目标角变化率算，限幅 ±10
yaw_speed_feedforward = DEGREE_2_RAD*(yaw - yaw_last_ref)*500.0f;
LIMIT_MIN_MAX(yaw_speed_feedforward, -10.0f, 10.0f);
// 电流前馈：按速度环设定值分三段给，弥补 GM6020 静摩擦
if      (ref >=  0.5f) yaw_current_feedforward =  500.0f;
else if (ref <= -0.5f) yaw_current_feedforward = -500.0f;
else yaw_current_feedforward = 500.0f * ref / 0.5f;   // 线性过渡区
  • 用 IMU 而非编码器做反馈：直接稳“绝对指向”，隔断齿轮回差、机械弹性对指向精度的影响。
  • 速度/电流前馈：在误差出现前先给动力，减小相位滞后与静差，起停更“跟手”不拖沓。
  • pitch 用达妙 DM 电机（自带更高带宽），同样以 IMU Pitch + Gyro[0] 闭环。

5 · 稳定性来源总结（可迁移清单）

#决策作用
1视觉误差卡尔曼滤波（位置+速度 2 态，自动降级）抗图像抖动；丢帧只预测不更新，不跳变
2增益随距离调度（mapping 500→1560）远近距离都不超调
3帧率门控（≥20Hz 才更新）+ 数据限幅脏数据/掉帧不甩头
4状态机（TURING→TRACKING→SEARCHING）丢目标主动扫回，全程无“死等”
5IMU 姿态闭环（1kHz）+ 速度/电流前馈快内环稳指向，隔离机械误差
6控制频率（200~500Hz）> 视觉帧率慢视觉不拖累快内环
7看门狗 Daemon（视觉/遥控离线检测）异常自动回安全态
8多圈角归并 round(θ/360)*360避免 ±180° 翻转跳变

6 · 与我们 25Efork 工程的对照启示

  • 同思路已具备：我们 B 轨也是“视觉误差 → 闭环 → 云台”，并已用 IMU 做反馈、加前馈。本项目印证了这条路线的正确性。
  • 可直接借鉴点：
    1. 视觉误差的卡尔曼滤波：我们现在用 One Euro / 低通，可评估换 2 状态 KF（位置+速度）——对“丢帧不跳变”和“保留趋势”更友好（B 轨已有 CenterTracker，可在误差域再叠一层 KF）。
    2. 距离自适应增益：把 px→角度 增益按距离调度，替代固定 PULSE_PER_PX，可显著改善远近一致的跟手/防超调手感。
    3. 帧率门控：我们已有 Vison_Frequency 类似量（B 轨有帧率计量），可加“≥阈值才刷新、否则保持”的门控，替代“丢帧即乱发”。
    4. 分段增益（粗调/精调切换）：与我们在“跟手 ↔ 柔和”跷跷板上的取舍同源，可用状态切换而非一个固定折中值。
  • 注意差异：该项目用“云台 IMU 绝对角闭环 + 视觉增量微调”，属于相对瞄准；我们若也用绝对角闭环，需注意与底盘运动解耦（其底盘多为零力）。
