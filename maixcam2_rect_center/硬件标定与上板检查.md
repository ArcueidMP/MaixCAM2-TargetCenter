# B 轨硬件标定与上板检查

适用于 `maixcam2_rect_center/` 的 SEARCH、视觉追踪、相机安装 IMU 和 MaixVision 图传。
目前没有这套机构的实测标定值，以下步骤用于取得这些值；不要把示例轴向或电机参数当成已经验证的结果。

## 1. 未标定时保持哪些门槛

当前配置保持：

```python
ENABLE_IMU_FEEDFORWARD = False
IMU_AXES_CALIBRATED = False
IMU_BIAS_DPS = None
YAW_PULSES_PER_DEG = 0.0
PITCH_PULSES_PER_DEG = 0.0
GIMBAL_GEAR_RATIO = 0.0
ENABLE_SCAN = False
```

未取得实际输出轴的脉冲/度时，SEARCH 显示 `UNCALIBRATED`，不发搜索运动。
IMU 的安装轴、零偏和脉冲/度未就绪时，不允许惯性补偿驱动电机。
`PULSE_PER_PX_* = 3.67`、现有 `DIR_SIGN_*` 也必须通过本机实测核对；普通视觉追踪不会因为
SEARCH 的角度门槛而自动禁用。初次接线、读 IMU 或检查图传时，先设 `ENABLE_GIMBAL=False`。

`SELF_TEST_PULSES` 的固定脉冲自检不依赖脉冲/度，会使电机运动；没有确认机构空间前不要点击。
同一时间只运行 B 轨主程序或一个标定程序，避免两个程序争用 UART/IMU。

## 2. 先核对串口和物理正方向

| 轴 | 串口与设备 | 引脚 | 驱动器地址 | 本项目的物理正方向 |
|---|---|---|---|---|
| yaw | UART2，`/dev/ttyS2` | B0/B1，`YAW_PINS` | `ADDR_YAW=2` | 云台向左转 |
| pitch | UART0，`/dev/ttyS0` | A28/A29，`PITCH_PINS` | `ADDR_PITCH=1` | 云台向上仰 |

两轴均需要显式 pinmap。UART0 同时是系统日志口，注意启动日志混入；依据启动日志中的
pinmap 回读、UART 打开结果和 ACK 判断链路，而不是只看电机是否通电锁轴。
驱动器需设置 `P_Serial=UART_FUN`、`UartBaud=115200`、正确 `ID_Addr`、`Checksum=0x6B`、
`Response=Receive`。微步数和电机每圈步数要与 `MOTOR_PULSES_PER_REV` 对应。

停止主应用，把机构放在行程中部，逐轴执行经过人工确认的少量相对脉冲，观察驱动器 CCW/CW
分别对应左/右、上/下。记录 `YAW_POSITIVE_CCW` 和 `PITCH_POSITIVE_CCW`：
物理正向由 CCW 驱动就填 `True`，由 CW 驱动就填 `False`。现有两项为 `True`，换接线或机构后要复核。
不要同时修改物理正方向与视觉反馈符号来掩盖一次接反。

## 3. 实测输出轴每度脉冲

这里测量的是减速机构之后的云台角度，不是电机转子角度。

1. 用量角器、角度刻度或可靠的角度传感器记录起始姿态。先消除该方向的齿隙，保持另一轴不动。
2. 向一个方向发送已知脉冲数 `P`，等待实际运动结束，测量输出轴转角 `Δθ`。
   单次 `pulses_per_degree = P / abs(Δθ)`。
3. 正、反方向各重复至少三次，记录脉冲数、实测角度、方向、转速与起止姿态。
   从较小行程开始，再扩大到工作区内可准确读数的行程。
4. 换向后先记录“多少脉冲尚未带来明显角度变化”，再测有效运动段。
   分开记录回差和比例，避免把整段齿隙当成每度脉冲。
5. 两个方向的结果应接近；明显不一致时先检查松动、限位、丢步、回差或角度读数，再填写配置。

将各轴实测值分别填入 `YAW_PULSES_PER_DEG`、`PITCH_PULSES_PER_DEG`。
只有减速比和电机每圈脉冲数都已确认时，才可用
`MOTOR_PULSES_PER_REV × GIMBAL_GEAR_RATIO / 360` 推导；减速比未知就保留 `0.0`。
不要用视觉标定的脉冲/像素数替代脉冲/度。

| 记录项 | yaw 实测 | pitch 实测 |
|---|---|---|
| 正向 `P`、`Δθ` 与重复结果 | 待测 | 待测 |
| 反向 `P`、`Δθ` 与重复结果 | 待测 | 待测 |
| 最终脉冲/度 | 待测 | 待测 |
| 换向回差与可用行程 | 待测 | 待测 |

## 4. 再测视觉脉冲/像素与方向符号

固定小车和靶纸，在实际工作距离、镜头、分辨率下测量。黑框全程留在视野内，另一轴不动。
优先采用 `raw_u/raw_v`，与当前 `AIM_USE_RAW=True` 的闭环口径一致。
当前 `LASER_MODE="fixed"` 使用 `LASER_U_NOMINAL/LASER_V_NOMINAL`，不会每帧寻找光斑。
先在电机停止时核对实际激光光斑的像素位置；可临时用 `LASER_MODE="detect"` 辅助读数，
确认识别到的是实际光斑后填回这两个常量，再恢复 `"fixed"`。镜头或激光安装变化后重新测量。

给轴发送已知 CCW 脉冲 `P`，实测静置前后靶心像素变化：yaw 用 `Δu`，pitch 用 `Δv`。
填写 `PULSE_PER_PX_YAW = P / abs(Δu)` 或 `PULSE_PER_PX_PITCH = P / abs(Δv)`。
在该轴的图像坐标中，CCW 使坐标减小时 `DIR_SIGN=+1`，使坐标增大时 `DIR_SIGN=-1`；
再把靶心置于光斑一侧，用小动作确认误差确实变小。方向错时先停车，再改对应轴的符号。

主程序支持 `CALIBRATE_AXIS="yaw"` / `"pitch"`，会打印脉冲/像素、方向、交叉项和回差。
先按机构和视野缩小 `CALIBRATE_PULSES`，降低 `CALIBRATE_RPM`，不要直接采用现有较大的标定行程。
确认本轮不运行 SEARCH、自检或 IMU 补偿；标定结束把 `CALIBRATE_AXIS` 改回 `""`。
该过程测的是图像比例，不能得到真实脉冲/度。

正反向重复并检查回到同一图像位置时的残差。`DEADBAND_PX` 应覆盖可重复的回差和静态抖动；
可参考至少为回差估计的 1.5 倍，再结合实际中心误差要求调整。
明显的跨轴图像位移应先检查相机横滚和安装，而不是增大闭环增益。

## 5. 测 IMU 安装轴与符号

板载 IMU 通过 `maix.ext_dev.imu` 的 LSM6DSOWTR 接口读取，陀螺仪单位为 **deg/s**。
以下程序只读原始 xyz，不驱动电机。在 B 轨目录运行；先停止其它 IMU 程序和所有电机。

```python
import time
from vision.imu_heading import MaixIMUSensor

sensor = MaixIMUSensor()
deadline = time.perf_counter() + 10.0
while time.perf_counter() < deadline:
    gyro = sensor.read()
    if gyro is not None:
        print("gyro xyz deg/s:", gyro)
    time.sleep(0.02)
```

让相机从水平、无初始横滚的姿态开始。先静置读零速基线，再只做 yaw 向左慢转、向右慢转，
观察哪个 xyz 分量变化及其符号；然后恢复水平，只做 pitch 向上、向下慢转。
可以人工缓慢转动已停止且适合手动转动的机构，或采用前面确认过的小角度单轴动作。
逐轴测量时不要转动车身或另一轴。

`IMU_YAW_AXIS` 表示“物理向左转时为正”的传感器单位向量；`IMU_PITCH_AXIS`
表示“物理向上仰时为正”的传感器单位向量。安装与传感器轴对齐时可选带正负号的坐标轴；
未对齐时应按实测向量求安装变换，不能仅选最大分量并声称已完成标定。
两向量必须为单位向量且相互正交，代码会检查。当前默认向量只是待核对的数学配置。

确认正反方向、轴间串扰和重复性后，才将 `IMU_AXES_CALIBRATED=True`。
每次重新开始姿态积分都从确认过的水平初始姿态启动；陀螺仪不能识别未知的初始倾斜，
也不能独立提供无漂移的绝对航向。当前实现在 pitch 接近大倾斜时会以
`ATTITUDE_OUT_OF_RANGE` 阻断补偿，阈值由 `IMU_MAX_PITCH_DEG` 控制。

## 6. 静止标定 gyro 零偏

小车轮电机、两轴步进电机及任何会带动 IMU 的机构都要完全停止。保持云台和车身静置，
不要在采集窗口点击自检、SEARCH、搬动相机或触碰车身。`stop()` 成功仅说明停车帧写出，
仍需确认实际机构已经停止。

下面的 API 程序请求标定，控制线程先停车，再阻断运动；即使安装轴尚未校准，零偏采集仍需静止。
它仅临时开启读 IMU，不修改保存的 `config.py`。主应用必须先停止，保证 UART/IMU 只由此程序持有。

```python
import time
from target_api import AimLoop, load_config

cfg = load_config(ENABLE_IMU_FEEDFORWARD=True,
                  IMU_AXES_CALIBRATED=False,
                  IMU_BIAS_DPS=None,
                  IMU_CALIBRATE_ON_START=False,
                  CALIBRATE_AXIS="", ENABLE_SCAN=False)
loop = AimLoop(cfg, enable_motors=True, with_laser=False)
try:
    if not loop.stop():
        raise RuntimeError("停车写入失败，先处理 UART 故障")
    input("确认车轮与云台实际完全停止，再按回车开始零偏采集：")
    if not loop.calibrate_imu_bias():
        raise RuntimeError("IMU 标定请求不可用")
    deadline = time.perf_counter() + cfg.IMU_BIAS_CALIBRATE_S + 5.0
    while time.perf_counter() < deadline:
        loop.idle()                 # 消费请求、收 ACK；不提交视觉/运动请求
        state = loop.imu_status()
        if state.get("calibration") == "READY":
            print("实测 IMU_BIAS_DPS =", state["bias_dps"])
            break
        if state.get("calibration") == "REJECTED" or state["state"] == "ERROR":
            raise RuntimeError(str(state.get("error") or "零偏标定失败"))
        time.sleep(0.01)
    else:
        raise RuntimeError("零偏采集未完成，请检查 IMU 和实际静置状态")
finally:
    loop.close()
```

把成功输出的 xyz 元组原样填入 `IMU_BIAS_DPS`。较大方差或较大均值会被拒绝；不要为了让运动中的
数据通过而放宽 `IMU_BIAS_MAX_STD_DPS` / `IMU_BIAS_MAX_DPS`。
首次初始化较慢、窗口内样本不足时也可能拒绝；确认传感器已持续采样和机构静置后重新请求采集。
驱动已有的 gyro 校准文件可被读取，但更换安装、温度或设备后仍需复核实际静止零偏。
静止窗口也无法可靠区分一切极慢匀速转动，因此人工确认静止仍是前提。

## 7. 逐步开启补偿，核对实际剩余角度

脉冲/度、视觉方向、IMU 安装轴和零偏都实测后，再启用 `ENABLE_IMU_FEEDFORWARD=True`。
完成普通视觉闭环和机械空间检查后，才把主应用的 `ENABLE_GIMBAL` 恢复为 `True`。
先使用小角度，观察正反方向及小车静止时是否误动；然后逐步扩大到较大的 yaw 转向，最后再测 90°。
每次扩大之前确认完整机构行程、线缆和光斑运动范围足够。保持初始 pitch 接近水平，另行小幅验证 pitch。

先让视觉看到黑框，完成捕获时间对齐的参考锁定，再暂时遮挡黑框、缓慢转动车身。
无视觉参考时 IMU 不会自行建立靶向。检查 `imu_status()` 的 `reference_locked`、`state`、`age_s`
以及实际电机方向。传感器过期、采样长间断或参考保持超时应停车，重新看到目标后再锁参考。
`IMU_HOLD_MAX_S` 是短时保持上限，不是无限制惯性追踪；`IMU_MAX_STEP_DEG`、`IMU_RPM`
和 `IMU_GAIN` 也应从保守值逐步验证。

相机安装 IMU 测到的是 **车身转动 + 云台实际转动**。例如车身左转 90°、云台已实际右转 60°，
相机剩余转动为左 30°，所需修正为右 30°。不能再次减去已经发送的 -60° 指令，也不能继续补偿整段 90°。
已请求的脉冲并不证明电机实际走完，视觉帧也不能叠加一次完整的 IMU 误差而重复修正。

保持 `IMU_SENSOR_MOUNT="camera"` 与实际安装相符。若 IMU 改装到车身，应单独测量云台实际角度；
底层 `base` 模式需要 `gimbal_deg` 实测位置，当前应用/AimLoop 没有提供这个硬件反馈通道。
仅修改配置为 `"base"` 不会获得可用补偿，不能把发送脉冲累计值当作编码器。

## 8. SEARCH 从小范围验证到 ±45°

先把 `SEARCH_YAW_DEG`、`SEARCH_PITCH_DEG` 缩小到机构已验证的范围，再逐步扩大；
完成每一步的正反向检查后，最后才使用 45°。任意点击姿态都需要留出每轴完整的正、负角度空间，
包括线缆、云台限位和相机附件。软件边界是相对点击启动时姿态，不是机构绝对限位保护。

SEARCH 路径为 yaw `0→+A→−A→0`，再 pitch `0→+B→−B→0`；这是两轴交叉搜索，
不是整个二维视场的栅格扫描。找到新鲜黑框时立即停车，再等待停车之后采集的新画面接入视觉追踪。
SEARCH 不依赖激光检测才能停车；命中和取消均不根据未完成的请求脉冲盲目回中。
只有完整走完六段时，才按命令序列回到启动端点，仍需实测核对实际回差。

第二次点击 SEARCH 可取消。API 调用 `loop.request_search()` 也是启动/取消切换，
请求由后续 `step()` / `idle()` 消费；`loop.stop()` 可明确停车和取消。
`search_state` 可见 `RUNNING`、`ACQUIRED`、`CANCELLED`、`UNCALIBRATED`、`DONE`、`FAULT`。
`DONE` 可能是完成或超时，详细原因在控制器的搜索状态中；`FAULT` 后不能继续动作。
当前 `SEARCH_TIMEOUT_S=60.0` 只是有界退出机制，不承诺 4 秒走完全部行程。

以下是独立的 AimLoop 调用例子，需先保存全部实测配置；主应用必须停掉。它启动一次寻靶，
通过真实相机帧交接视觉追踪，并在退出时停车：

```python
import time
from maix import app, camera, image
from target_api import AimLoop, load_config

cfg = load_config()
assert cfg.YAW_PULSES_PER_DEG > 0 and cfg.PITCH_PULSES_PER_DEG > 0
cam = camera.Camera(cfg.CAMERA_W, cfg.CAMERA_H, image.Format.FMT_GRAYSCALE,
                    fps=cfg.CAMERA_FPS, buff_num=cfg.CAMERA_BUFFERS)
loop = AimLoop(cfg, enable_motors=True, with_laser=True)
try:
    if not loop.request_search():
        raise RuntimeError("SEARCH 请求不可用")
    last_log = 0.0
    while not app.need_exit():
        frame = cam.read()
        captured_at = time.perf_counter()  # 与 IMU 使用同一单调时钟
        if frame is None:
            loop.idle()
            continue
        result = loop.step(frame, now=captured_at)
        if captured_at - last_log >= 0.5:
            print(result.get("search_state"), result.get("aim_state"),
                  result.get("control_source"), result.get("dx"), result.get("dy"))
            last_log = captured_at
finally:
    loop.close()
    cam.close()
```

`AimLoop` 不负责显示或触摸；完整显示、触摸按钮和图传可使用可复用应用 API：

```python
from main import BUILD_ID
from target_api import TrackingApplication, load_config

TrackingApplication(load_config(), BUILD_ID).run()
```

## 10. 验证真实 MaixVision 图传、30fps 与 4 秒目标

保持 `DISABLE_MAIXVISION_STREAM=False`，通过 MaixVision 连接设备并打开预览。
本实现复用设备会话和本机 WebSocket 桥 `127.0.0.1:7899`，编码/发送由独立进程承担。
必须在实际板端核对本机桥版本和协议握手；PC 协议桩通过不能代替此项。
观察 `[preview] MaixVision stream=ready`，并确认电脑预览收到持续变化的新画面。
`connecting` 是待连接，`retrying` 是重连中，`unsupported` 表示协议不兼容，`paused` 表示客户端暂停。
先检查会话、桥接服务、端口与预览开关；不要把没有图传当成 30fps 已恢复。

先以 `ENABLE_GIMBAL=False` 连续运行至少 60 秒，再在标定完成后加入静态追踪、移动、寻靶和 IMU 保持场景。
分别记录 `[perf]` 的 `capture`、`disp`、`detect_fps`、`low1`、`age` 和丢帧数。
前三项是采图、本地显示和识别吞吐，不等于电脑端 MaixVision 接收帧率。
图传端可从运行中的 `TrackingApplication.preview.stream.status()` 读取 `sent`，用计数差除以时间；
另外记录电脑端预览的新帧和可见延迟。断开、重连、暂停预览时，也应确认本地显示/识别/串口继续工作。
`SHOW_FPS=30`、`CAMERA_FPS=30` 都是目标设置，最终用板端连续计数和实际收到的帧验收。

4 秒测试的起点应按题目统一为小车停下/发出寻靶指令，终点为激光进入要求的靶心容差且持续稳定。
同时记录首次检出、停车、首张停车后采图、首次进入死区四个时刻，区分寻靶时间和收敛时间。
先测靶纸已在视野内，再测视野外不同 yaw/pitch 偏角；正反方向、不同距离与照明每种至少重复五次，
用录像或外部计时记录真实光斑，报告成功率、最慢耗时和最终偏差。固定光斑像素只是相机内标定值，
不能单凭 API 的 `SETTLE` 状态声称激光实物已经命中。
