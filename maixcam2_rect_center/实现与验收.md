# 附件规格对应关系与验收边界

输入：用户附件《项目生成提示词.md》。工作基线：获取后的 upstream/main `7b36b32`。
本轮重构 B 轨并复用主线已验证的协议/渲染/几何逻辑；不从旧旁支合并代码，不修改 A 轨应用。

| 规格 | 实现 | 回归 |
|---|---|---|
| Canny→Otsu、暗带、缺边、宽半径、rank | contour_locator、rectangle_center | performance、real_scene、images_e2e |
| mm↔px单应、warp独立中心 | rect_geometry、rectangle_center | tracking、real_scene |
| 匀速卡尔曼、时间和有限性 | kalman_filter | kalman |
| 快移预测、同帧ROI→全图 | rectangle_center | tracking、runtime_performance |
| ZDT相对位置、ACK/E2、短写检测 | stepper_link | gimbal_aim、extension_review |
| 渐进增益、动作等待、新采图、停机 | gimbal_aim、aim_control | gimbal_tracking、aimloop_tracking |
| 自检、开环标定、按钮扫描 | gimbal_self_test、gimbal_calibrate、gimbal_search | main_self_test、gimbal_search、extension_control |
| 官方IMU、相对四元数、历史对齐 | imu_heading、aim_control | imu_heading、imu_turn_tracking |
| 最新帧槽、显示池、触摸、资源释放 | vision_worker、preview、app_runtime | app_runtime、runtime_performance |
| protocol-0 客户端、独立进程、mmap/flock | maixvision_stream | preview_stream |
| API、单文件、25文件清单 | target_api、build_single、check_app | target_api、check_pc |

规格中存在以下相互矛盾或需要测量才能成立的表述，本轮采用可执行口径：

- 自检按详细序列的六段执行，保留原主线六段行为；不采用末尾验收项的“四步”。
- Display 在主线程创建、关闭，show 按明确的显示线程要求执行。线程存活时不关闭底层设备。
- “≤2张掩膜”按一次搜索计；ROI→全图不可省略，因此同一失锁帧总计最多4张，日志如实累计。
- 未标定 SEARCH 采用固定脉冲。提前收段时不知道实际已执行脉冲，报告比例上界；完整段才报告估计。
- “板端不再312ms”需要上板测量。本轮保证有限图像尺寸、轮廓/候选上限、最多两级定位和有限精修轮数，
  并拆除原生图传等待路径；不将 PC 耗时当成板端性能保证。
- 两张真实正样本未随附件提供、也不在 upstream；相关检查明确 SKIP，不用合成图冒充真机数据。
- 图像正视中心的灰度剖面采第10分位作为暗档，避免长边黑胶带总占比约12%时第15分位误采到亮面。
- 新的每轴发散保护只在已完成动作后的新观测上累计，默认连续6次显著增大才故障；断流清历史。
